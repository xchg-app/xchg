# Gotchas

- **Клиент обязан работать на bash 3.2 — это системный bash macOS.** Ассоциативных массивов там нет (`declare -A` падает до разбора аргументов), поэтому реестр хабов — параллельные индексные массивы с геттерами `hub_path/hub_remote/hub_login`. Проверять только живым прогоном `tests/bash32.sh`: статические grep'ы находят не всё.
- **Разворот пустого массива под `set -u` в bash < 4.4 — «unbound variable».** Писать `${a[@]+"${a[@]}"}`: так падали `hub init` и `status` при первом запуске, когда хабов ещё нет.
- **Переменная вплотную к не-ASCII (`«$p»`) под `set -u` падает с `p\xc2: unbound variable`** в части сборок bash (macOS, bash 5.3): первый байт кириллицы или ёлочки уходит в имя. Писать `«${p}»`; тест ловит такие места awk'ом.
- **`local h="$1" d="$(hub_path "$h")"` не работает под `set -u`.** Все значения раскрываются до присваивания, `$h` ещё не задан. Всегда две команды: `local h="$1"; local d=...`.
- **`[ cond ] && cmd` последней командой функции или подстановки роняет скрипт под `set -e`,** если условие ложно. Заканчивать `true`, писать `if`, или добавлять `return 0`. На этом уже ловились `conf_add_hub`, `init_hub_repo` и `cmd_inbox`.
- **Курсор чтения — список имён прочитанных файлов, а не «до какого места».** Отметка-водомер теряла бы сообщение, запушенное задним числом (коллега был офлайн, время в имени файла — время создания). Список заодно самоочищается: при записи из него выбрасываются имена, которых в каталоге уже нет.
- **Курсор заведён на пару агент+адрес.** Иначе агент в `api`, прочитав заметку в `all`, «съедал» бы её у агента в `web` — а заметку должен разнести к себе каждый.
- **`xchg send` помечает собственное сообщение прочитанным** — иначе оно возвращалось бы автору в первом же хуке.
- **`claim` = `git mv` в свой адрес, а не флаг в файле.** Никаких правок чужого сообщения и никаких блокировок: атомарность даёт push, проигравший узнаёт владельца по тому, где теперь лежит файл (`claim_owner`).
- **Откат проигранного claim ограничен `ahead == 1`.** `reset --hard @{u}` выполняется, только если наш claim-коммит единственный незапушенный; иначе печатается предупреждение, чтобы не снести чужую незапушенную работу.
- **`git mv` не знает `-q`** (в отличие от `git rm -q`).
- **`sync_hubs` может убить `git pull` по дедлайну посреди rebase** — `hub_sync` при старте проверяет `.git/rebase-merge|rebase-apply` и делает `rebase --abort`.
- **`self_update` молчит в грязном клоне** (`git status --porcelain` не пуст) — чтобы не дёргать репозиторий разработчика.
- **`help` и `version` обрабатываются до `load_conf`:** именно они объясняют, как чинить сломанный конфиг.
- **Тесты запускаются из репозитория xchg,** поэтому проект сессии по умолчанию — `xchg`. В тестах команды выполняются через `in_api`/`in_web`, которые делают `cd` в песочные репозитории.
- **Правки клиента скриптом делать только с проверкой совпадения** (`assert a in s`): молча не сработавшая замена выглядит как успешный патч, а ловится потом тестом — если тест на это место есть.
- **Регистрация идёт через `hub_push`, а не просто `git add`.** `register_me` и `agent_passport` проверяют `git diff --cached --quiet` перед коммитом: без этого повторный `projects add` создавал бы пустые коммиты.
- **Хабы, созданные старыми клиентами, содержат русские подписи** («Репозиторий:», «Человек:», заголовок `| login | имя | алиасы | контакт |`). История хаба не переписывается, поэтому то, что клиент читает обратно, понимает обе формы: `project_card` ищет `Repository|Репозиторий`; строку заголовка книги отсекает первая колонка `login`, одинаковая в обеих версиях.
- **Отказ хаба (`remote: xchg: …` из pre-receive) — не сбой сети.** `hub_push` не повторяет попытки, откатывает свой коммит (`HEAD~1`: после `pull --rebase` он последний) и выходит с кодом 1; иначе sync падал бы вечно. Поэтому stderr push собирается, а не глушится. `hub_sync` коммиты не откатывает — только показывает причину.
- **Реестр людей — contacts.md, а не `people/<login>/`.** Каталог и письма ушедшего остаются в истории; доступ отзывают удалением строки. Поэтому `resolve_user` каталог не смотрит.
- **`x=$(f "$x") || die "…${x}…"` печатает пустоту:** присваивание случилось до `||`. Результат — в отдельную переменную.
- **Участие в проектах выводится из каталогов `projects/<p>/<user>/`, а не из колонки в contacts.md.** Ручная колонка врала бы; каталог создаётся вместе с паспортом агента.
- **`wait` будит на «не показанное», а не на «ящик не пуст».** Открытая задача лежит в ящике до `done`; если будить на непустой ящик, агент в фоне просыпался бы от неё бесконечно. Ключ списка показанного — имя файла, потому что `claim` и `done` переносят файл, но имя не меняют.
- **bash дочитывает скрипт по ходу исполнения.** Если `bin/xchg` переписать на месте (тот же inode: запись скриптом, часть редакторов), пока команда работает, после неё bash прочтёт обрывок нового файла — `command not found` или `syntax error` и чужой код выхода, хотя сама команда отработала. `git pull` и `/plugin update` файл заменяют (новый inode), работающий процесс читает старую копию и не страдает. Защита — весь запуск внутри `main`, последняя строка файла `main "$@"; exit $?`: она читается целиком до исполнения, а функции разобраны заранее. Тест переписывает копию клиента во время `wait`.
- **Хук отличает старт сессии по JSON на stdin (`hook_event_name`).** `SessionStart` показывает всё открытое, остальные вызовы `--brief` — только непоказанное. stdin читается через `read -t 1`: с терминала не читается вовсе, из открытой пустой трубы — не дольше секунды.
- **`claim` снимает `mute` со взятой задачи.** Ключ пометки — имя файла; без этого задача, которую агент сначала заглушил, а потом взял себе, пропала бы из его же ящика.
- **Харнессы по-разному ставят пакет** (проверено настоящими CLI): Claude Code ставит плагин из подкаталога и разворачивает симлинки в файлы; Codex из подкаталога **выбрасывает симлинки**; Gemini ставит расширение только из корня репозитория и копирует его целиком, вместе с `.git` (поэтому `PLUGIN_MODE` определяется по пути, а не по отсутствию `.git`). Отсюда раскладка: Claude Code — `harness/claude-code/` на симлинках, Codex и Gemini — корень.
- **Байты вложений — мимо фильтров git.** С `core.autocrlf` (на Windows и в WSL он часто включён) `git hash-object -w` без `--no-filters` меняет CRLF в текстовых файлах: html-страница или лог приезжают другими, и хеш не совпадает с исходником. Запись — только `hash-object -w --no-filters --stdin`, чтение — только `cat-file blob`, никакого checkout. Тест гоняет вложения с включённым `core.autocrlf`.
- **Клон по пути копирует все объекты.** `git clone /path/bare` хардлинкует весь каталог объектов, в том числе то, что достижимо только из `refs/xchg/att/*`, поэтому «обычный клон вложений не тянет» в тесте проверяется клоном по `file://`: так ведёт себя любой сервер.
- **Проверка доступа — только через git.** `hub check` делает `git ls-remote`, а не `ssh <host>`: ответ голой ssh-сессии зависит от сервера (у GitHub и GitLab код возврата не нулевой при рабочем ключе), да и https так не проверить. Заодно не надо разбирать remote на части и подставлять его в `eval`.
- **Каталог хуков Cline не угадываем.** Путь зависит от сборки (есть открытый баг про WSL), поэтому `install` пишет файлы только в тот каталог, который уже есть, иначе печатает, что создать. Иначе в `~/Documents` появляется дерево, которое ничто не читает.
- **Hermes и Cline вживую не проверены.** Аккаунтов нет, поэтому их поддержка написана по документации и покрыта только тестами на форму вывода и на то, что пишет `install`. У Cline файловые хуки — старший механизм (страница документации теперь ведёт на плагины SDK), каталог общих хуков зависит от сборки (есть открытый баг про WSL), работают только на macOS и Linux, а список событий в блоге и в коде расходится (`TaskResume` против `TaskComplete`). У Hermes ответ хука `on_session_start` игнорируется — «всё открытое» показываем по `is_first_turn` в `pre_llm_call`.
- **Общих `hooks/` и `commands/` в корне быть не должно.** В каждом пакете свой `hooks/hooks.json`, и общим он быть не может: у Gemini событие промпта `BeforeAgent` (на неизвестное событие он печатает предупреждение), таймаут в миллисекундах и своя подстановка корня (`${extensionPath}` против `${CLAUDE_PLUGIN_ROOT}` и `${PLUGIN_ROOT}`). Имена `hooks/` и `commands/` не принадлежат никому конкретно, поэтому в корне репозитория их нет вовсе: файлы лежат в `harness/<имя>/`, а в пакет попадают сборкой. Тест это стережёт.
- **Пакет обязан быть самодостаточным: симлинков не переживёт.** Установка Gemini и Codex копирует каталог, и относительная ссылка превращается в абсолютную на исходник, которого у пользователя нет (у Gemini это временный клон, его удаляют сразу). Только Claude Code разворачивает ссылки в файлы. Поэтому `tools/package.sh` копирует `bin/`, `skills/`, `hub/` настоящими файлами (`cp -RL`).
- **Gemini не понимает короткую форму `owner/repo`.** `gemini extensions install xchg-app/gemini-plugin` отвечает «Install source not found» (0.60.0, вопреки документации): адрес нужен полным URL. У `claude plugin marketplace add` и `codex plugin marketplace add` короткая форма работает.
- **Gemini ставится только из корня репозитория.** `gemini extensions install` принимает `owner/repo`, URL репозитория или локальный путь; URL с `/tree/<ветка>/<каталог>` отвергается («Expected "owner/repo" or a github repo uri»), а `--ref` — это git-ref, а не путь. Если у репозитория есть релизы, он сначала пробует ассет из последнего (единственный ассет без имени платформы), и лишь потом `git clone`. Отсюда и отдельный репозиторий пакета.
- **Gemini не добавляет в контекст обычный stdout хука** — показывает его пользователю. В контекст всех трёх попадает только JSON `hookSpecificOutput.additionalContext`; поэтому клиент из хука всегда отвечает JSON. Пустой вывод (0 байт) допустим везде, `{}` не печатать.
- **`hooks/hooks.json` не упоминать в `manifest.hooks`.** Стандартный файл Claude Code подхватывает сам; явная ссылка на него — дубль, и плагин не загружается (`claude plugin list`: `failed to load`). `claude plugin validate` этого не ловит, поэтому `tests/run.sh` ставит плагин в отдельный `HOME` и смотрит статус в `plugin list`.
- **`case` внутри `$( )` в bash 3.2 ломает разбор: `)` шаблона закрывает подстановку.** Писать шаблоны со скобкой впереди — `case "$p" in (*/done/*) …;; (*) …;; esac`. `bash -n` этого не видит (подстановка разбирается при исполнении), поэтому тесты сверяют вывод точно, а не по вхождению слова: сломанный вывод содержит куски скрипта с теми же словами.
- **`hub_sync` дотолкивает непушенное только после успешного pull и вне дебаунса `--max-age`.** Хаб в этот момент заведомо доступен; иначе при лежащем хабе хук на каждый промпт ждал бы таймаута push. Провал push выставляет `PUSH_FAILED`, и `main` возвращает 4 — даже если сама команда отработала.
